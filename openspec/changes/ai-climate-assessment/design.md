# Design

## Context

Astro currently builds static pages with React fetching public EONET records. The existing evidence Worker only schedules ingestion. Evidence retrieval uses compatible generation profiles, hybrid ranking, two chunks per publication, and immutable citation lookup. No Zod dependency exists; domain and adapter boundaries use native runtime checks. See proposal.md for motivation.

## Goals / Non-Goals

**Goals:** A small secure pipeline that operators can precompute for real events and readers can inspect; additive persistence with verified references and conservative defaults.

**Non-Goals:** New Workers, framework migrations, queues, autonomous agents, geocoding, public expensive generation, and repeated automatic retries of rejected scientific responses.

## Decisions

1. Extend the evidence Worker's fetch handler. GET reads persisted results; bearer-protected POST resolves an event by ID and explicitly assesses/reassesses it. An allowlisted frontend origin can read results. A local CLI also generates results. This preserves static hosting instead of adding an Astro SSR adapter or another Worker.
2. Reuse retrieval through four deterministic queries containing dates, category, title, coordinates, available label, summary, and magnitude. Request twelve chunks each, enforce two per publication/query, round-robin diverse candidates into a twenty-four-passage budget, and pin/check a corpus snapshot around work. Similarity is never sent as confidence.
3. Require JSON over Featherless chat completions, default live-tested Qwen3-32B, temperature 0.1 and 4000 tokens, configurable. Request response_format json_object and the documented chat_template_kwargs enable_thinking false; an isolated live format probe verified the JSON option affects output. Reuse HTTP timeout/size controls and native required-field validators, constructing only the allowed domain shape and discarding unknown fields. Generation has no transport retries. Only missing required JSON fields permit repair with explicit validation feedback, up to three attempts per phase; additional fields, invalid values/JSON and scientific rejection never cause another model call. The usual draft/review cost is two completions, at most six with missing-field repairs.
4. Draft only claim text, exact passage selections/IDs, requested levels, uncertainties, and indices selecting summary/cause/connection claims. Resolve all source metadata on the server. A separate evidence-review prompt checks entire statements, explanations, limitations, uncertainty, essential synthesis steps, contradictory passages, analogue comparability, and relationships. No private reasoning is persisted.
   A later live check caught a model-altered quotation. Draft citations now select server-defined segment IDs instead of generating quoted text. Segments retain exact contiguous source text and are at most 1200 characters; the server resolves the selected ID to the authoritative passage/chunk before review and persistence. This reduces output tokens and makes model-authored quotations impossible in the structured draft contract.
   The large JSON-object trial exceeded citation-array bounds. An additional live JSON-schema probe succeeded, so real draft/review calls use strict JSON-schema constraints for required keys, enum values, retrieved chunk IDs and four-claim/four-citation limits. JSON-object mode remains the adapter default when no schema is supplied. Semantic acceptance is still independently checked.
5. Deterministic checks enforce retrieved IDs, exact quotation containment, immutable metadata equality, complete review coverage, and same-event name/date anchors before direct attribution. Direct evidence requires an actual attribution-study format plus named-event/time passage anchors and reviewer support. Generic names or sparse dates cannot meet this conservative gate. General mechanisms cap evidence at low and influence at none; applicable event context plus synthesis can permit medium, never high. Contradictions lower caps and require limitations. Semantic entailment remains a model-assisted check, not a mathematical guarantee.
   Claim types describe whether a finding is explicitly reported, synthesized across publications, or a general mechanism. They do not determine event relationships: an explicitly reported analogue finding remains indirect, and cannot transfer its contribution level to the assessed event.
6. Add service-only assessment/citation tables and invoker RPCs for snapshot, latest read, and atomic save. Snapshot hashes active generation and current version manifest, allowing stale detection even for newly added uncited evidence. Event hashes exclude fetch timestamps. Old immutable citations remain resolvable and saved assessments are retained as history. Save locks the corpus and rejects snapshot drift. Failed generation never replaces prior valid content.
7. Add a dedicated React assessment panel in EventDetail, independent level cards, linked claim citations, source grouping by publication and relationship, exact passages, explicit no-direct message, and honest unavailable/error/stale states. Reading includes the event hash to detect changed event data without a fresh provider request on every page load.
8. Add an operator-only CLI for sequential discovery using EONET date/category windows within the last three calendar years. Deduplicate candidates, prioritize named records, reuse current assessments, emit each outcome immediately, and stop at a target count, candidate limit, or hard completion-call budget. An explicit resume report excludes previously attempted event IDs across runs; each resumed run gets its own requested budget and target. A connection means a validated completed assessment with cited findings, including indirect findings with influence none. Preserve insufficient and failed outcomes in the report; selecting examples is not evidence of a population-wide attribution rate.
9. Remove numeric provider IDs from named-event identity comparison, normalize punctuation and diacritics, and accept full or abbreviated source months. Numeric IDs are not scientific identity requirements. Country-only unnamed fires still lack a distinctive event identity and remain indirect. Date compatibility, actual attribution passages, scientific review, and conservative levels remain mandatory. New assessments reject events whose first reported observation lies outside the three-year window; older scientific publications remain eligible evidence. Increment the assessment policy version to flag old saved results for explicit reassessment.

## Risks / Trade-offs

10. The user authorized production deployment and automatic processing on 2026-10-09. Add a service-only event catalog and singleton lease/cursor. Every ten minutes refresh recent reports and one historical week, splitting saturated windows rather than silently truncating records. Process all discovered categories progressively, with a six-completion budget, a twelve-minute run limit and ninety-second scheduled completion timeout. Persist the attempted event fingerprint, policy and model before generation so failed/interrupted responses do not automatically repeat. Event/policy/model changes can make records pending; corpus changes flag results stale without repeatedly regenerating the whole catalog.
11. The default globe view reads validated completed assessments with cited findings, including indirect findings with influence none. Keep the separate live and demo views, and show aggregate pending/insufficient/failed progress. Public reads never invoke providers, embeddings or generation. Deploy both existing Workers and preserve backend-only credentials.
12. Bound scheduled external requests independently of model calls: at most 48 requests, no automatic transport retries, three reserved final-write slots and a conservative admission check before starting another event. Batch immutable citation reads with a service-only additive RPC and commit discovery progress before generation. This keeps the existing Worker within the Free plan's 50 external-request limit; a normal fresh assessment generally occupies one invocation. Scientific rejection still does not retry, and untouched records remain pending for a later cron.

- Model-based semantic review can miss errors → exact reference checks, conservative ceilings, explicit AI label, and human review of demo assessments.
- Missing place labels and named-event/date anchors reduce direct recall → retain useful indirect findings and explain missing specificity; never guess location.
- Corpus changes invalidate a long request → atomic rejection and explicit rerun, preserving old results.
- Two generative calls cost more → precompute a handful of events and persist; bounded retries and no public generation.
- Large-passage review exceeded the initial 90-second deadline in a live preview → use a configurable 180-second default (maximum 300 seconds); keep no partial publication.
- Provider/model plan access and production migrations are external dependencies → validate offline, provide capability/live commands, report actual results separately, do not expose secrets or auto-deploy.

## Migration Plan

The study-first follow-up supersedes chronological scheduled backfill: select at most two current attribution-study versions per invocation, derive bounded date/category EONET lookups from study metadata or lead dates, and match distinctive event/place words against study text. Country-only records must match the title/opening event paragraph, excluding researcher affiliations. Named events take priority over generic country records in the matched queue. Persist lookup outcomes by immutable study version, rechecking completed lookups after seven days, incomplete lookups after one hour, and selecting corrected versions afresh. Unsupported hazards, missing dates and out-of-window study periods consume no provider/model calls. Only study-matched catalog records enter scheduled assessment; the existing chronological cursor/history and assessments remain intact. Matching is a discovery hint, never scientific support. Retain the singleton lease, 48-request cap, final-write reserves, model/runtime bounds and unchanged-failure exclusion. Add service-only study lookup persistence/RPCs, then execute bounded live runs and inspect saved citations for demonstration coverage. Model input exposes the unchanged same-event guard's prerequisite result per chunk, and prompts prohibit duplicate chunk citations and direct labels without those anchors; final scientific validation remains authoritative.

Run local migration/pipeline checks. Review/apply additive migration using the existing Supabase workflow, configure server secrets and allowed origin, verify Featherless access, generate/review real event assessments, deploy the existing Worker with a route, and build the frontend with its public API URL. Roll back runtime/UI while retaining assessment and immutable citation history.
